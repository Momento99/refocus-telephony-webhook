# Manager Portal — план разработки

**Subdomain:** `manager.refocus.asia`
**Аудитория:** нанимаемый управляющий сети из 5 оптик Refocus
**Главное требование:** mobile-first, PWA, удобно с iPhone в кармане
**Принцип доступа:** view-mostly — управляющий видит всё, действия с финансовыми последствиями (штрафы, премии, закупки) только **предлагает** владельцу.

---

## 1. Концепция и границы

### Зоны ответственности управляющего

1. **Операционка и продажи** — план/факт по выручке и среднему чеку, возвраты, провалы.
2. **Персонал** — посещаемость, дисциплина, разбор инцидентов, эскалация найма/увольнений.
3. **Качество сервиса** — Service QA (аудио/WhatsApp/Instagram), жалобы клиентов, реакция на красные сигналы.
4. **Склад и закупки** — мониторинг дефицита линз/оправ/расходников, предложение закупок.
5. **Клиент-менеджмент** — повторные покупки, лояльность, реакция на низкий фидбэк.
6. **Координация** — еженедельный отчёт владельцу, эскалация критичных вопросов.

### Что управляющий НЕ делает через портал

- Не выставляет штрафы и премии напрямую — только предлагает.
- Не утверждает закупки — только формирует список и отправляет владельцу.
- Не видит P&L, налоги, дивиденды, контракты франчайзи.
- Не управляет тарифами линз, ценообразованием, конфигурацией системы.
- Не управляет бюджетом и финансовой моделью.

## 2. Архитектура

### Технологический стек

Идентичен `refocus-franchise-portal` для переиспользования компонентов:

- Next.js 16 (App Router)
- React 19, TypeScript 5
- Tailwind CSS 4
- Supabase 2.103 (тот же проект `hbvuwnzemdifaapktaol`)
- ECharts 6 для графиков
- lucide-react, react-hot-toast
- next-pwa или Serwist для PWA + web push

### Деплой

- **Хостинг:** Vercel (новый проект `refocus-manager-portal`)
- **Домен:** `manager.refocus.asia` (CNAME → `cname.vercel-dns.com`)
- **Репозиторий:** новый `refocus-manager-portal` на GitHub (приватный)
- **CI/CD:** Vercel auto-deploy с main-ветки

### Авторизация

- **Таблица:** новая `manager_users` (отдельно от `franchise_users`, чтобы не путать)
  ```
  id            UUID PK
  login         TEXT UNIQUE
  pin_hash      TEXT
  full_name     TEXT
  branch_ids    UUID[]    -- массив филиалов, к которым есть доступ
  push_token    TEXT      -- web-push subscription
  telegram_chat_id TEXT   -- для дублирования critical-пушей
  is_active     BOOLEAN
  created_at    TIMESTAMPTZ
  ```
- **RLS:** доступ ко всем views/RPC ограничен `branch_ids` из JWT-клейма.
- **Сессия:** sessionStorage + heartbeat каждые 5 мин для авто-расширения; авто-logout через 12 часов бездействия.
- **Биометрия:** при повторном входе с того же устройства — Face ID / Touch ID через WebAuthn (фаза 2).

### Source of truth для данных

| Тема | Источник |
|---|---|
| Заказы и выручка | `orders`, `orders_view`, `v_payroll_branch_turnover_daily` |
| Зарплата | `v_payroll_daily`, `v_payroll_monthly_ui` |
| Посещаемость | `attendance_sessions` (включая `last_heartbeat_at`) |
| Service QA | RPC `rpc_operator_full_scores`, `v_employee_discipline_status` |
| Расходники | `pos_consumables`, RPC `pos_consumables_snapshot` |
| Дефицит линз | `lens_purchase_batches`, `v_sokuluk_lens_needs_agg` |
| Сверка | `v_reconciliation_weekly_branch_income`, RPC `reconciliation_overview` |
| Клиенты и фидбэк | `customers`, `customer_orders_view`, `employee_feedback_responses` |

**Новые RPC для multi-branch агрегации** (нужно написать в Supabase):

- `manager_today_summary(branch_ids[])` — карточки филиалов на «Сегодня»
- `manager_branches_period(period, branch_ids[])` — сравнение филиалов
- `manager_active_shifts(branch_ids[])` — кто сейчас на смене
- `manager_open_signals(branch_ids[])` — красные сигналы для inbox
- `manager_inventory_summary(branch_ids[])` — дефицит по сети

## 3. UI / Дизайн-система

### Базовые принципы

- **Bottom-nav** из 5 иконок (НЕ sidebar). Закреплён внизу с safe-area-inset для iPhone.
- **Тёмная тема** по умолчанию: фон `#0F172A` (slate-900), текст `slate-50`, акцент `cyan-500`.
- **Цвета и типографика** — наследуем из CRM design-system (см. `CLAUDE.md`).

- **Skeleton-loaders** при загрузке, никаких пустых экранов с спиннером.
- **Haptic feedback** на тапы и свайпы (где Web Vibration API позволяет).

## 4. Экраны

### Экран 1. «Сегодня» (главный)

URL: `/today`

Сверху вниз:

**A. Сетевой блок (3 крупные цифры)**
- Выручка сети сегодня · кол-во заказов · средний чек.
- Под каждой — крошечный тренд vs вчера (зелёная/красная стрелка с %).

**B. Карточки 5 филиалов (вертикальный список)**

Каждая карточка:
```
┌─────────────────────────────────┐
│ 🟢 Бишкек-1 Сокулук      87%   │
│ ₽42 350 · 12 заказов · 3 продавца│
│ ▓▓▓▓▓▓▓░░░ план 87%             │
└─────────────────────────────────┘
```
- Зелёная точка = есть активный heartbeat от хотя бы одного терминала.
- Красная точка = терминалы не отвечают / никто не открыл смену.
- Жёлтая = низкая активность (нет заказов > 3 часов).
- Прогресс-бар к дневному плану выручки.
- Тап → детальная страница филиала.

**C. 🚨 Открытые красные сигналы (compact list)**
- Service QA: грубость в звонке вчера в филиале X
- Опоздания на смену > 30 мин
- Дефицит линз < 7 дней по семейству Y
- Заказ в работе > 10 дней без движения
- Жалоба клиента (рейтинг ≤ 2 в фидбэке)

Каждый сигнал — карточка-свайп: ✅ закрыть · 💬 ответить · ⬆️ эскалировать владельцу.

**D. 💬 Непрочитанные сообщения** (если оставите чат с франчайзи или сотрудниками).

---

### Экран 2. «Филиалы»

URL: `/branches`

**Верх:** чипы периода — `Сегодня · 7д · 30д · Месяц` (segment control).

**Тело:** карточки-строки 5 филиалов с метриками за выбранный период:
- Выручка · % плана · средний чек · заказов · возвраты · возвраты %
- Сортировка тапом по любому полю.
- Свайп влево по карточке → быстрые действия: «Открыть детали», «Сравнить с лидером».

**Внизу:** компактный bar-chart «Выручка по филиалам» через ECharts.

**Drill-down (тап по филиалу) → `/branches/[id]`:**
- График выручки по дням за период.
- Структура оплат (наличные/карта/QR) — pie chart.
- Топ-3 продавца филиала за период.
- Состояние склада этого филиала (компактный блок).
- Открытые сигналы по филиалу.
- Кнопка «Эскалировать владельцу» → bottom-sheet с полем комментария.

---

### Экран 3. «Люди»

URL: `/people`

**Сверху:** 3 chip-таба — `Смены · Зарплата · Качество`.

#### 3.1. «Смены»
- Реалтайм список через подписку на `attendance_sessions` Supabase realtime.
- Карточка каждого активного сотрудника:
  ```
  Айбек · Бишкек-1
  🟢 На смене с 09:01 (4ч 32м)
  Заказов: 3 на ₽12 400
  Фокус: 87% (отвлечений 4)
  ```
- 🔴 Если heartbeat прерван > 5 мин — красный бейдж «Терминал не отвечает».
- Long-press → bottom-sheet: «Отправить пуш сотруднику», «Позвонить», «Открыть профиль».

#### 3.2. «Зарплата»
- Список всех сотрудников сети, текущий месяц.
- Карточка: имя · филиал · план/факт зарплаты · штрафы · премия · статус.
- Тап → детализация по дням (читаем `v_payroll_daily`).
- **Действие «Предложить премию/штраф» →** bottom-sheet с суммой, причиной, периодом → создаёт запись в новой таблице `manager_suggestions` со статусом `pending` → пуш владельцу. Управляющий **НЕ** меняет `payroll_adjustments` напрямую.

#### 3.3. «Качество»
- Список сотрудников с цветовым рейтингом Service QA (0-100, шкала: 80+ зелёный, 60-79 жёлтый, <60 красный).
- Сводный скор: аудио 50% · WhatsApp 30% · Instagram 20% (из CRM-формулы).
- Тап → AI-советы (читаем готовые из CRM `/admin/ai-employee-messages/advisor`).
- Список «Критические события» за неделю — грубости, давление, перебивания.

### Экран 4. «Склад»

URL: `/inventory`

**A. Три карточки-индикатора:**
- 🔴 Линз дефицит: N семейств
- 🟡 Оправ мало: M моделей
- 🟢 Расходники: всё ок / N филиалов в дефиците

**B. «Что нужно заказать на этой неделе» (агрегировано по сети):**
- Список из `lens_purchase_batches` + `v_sokuluk_lens_needs_agg`.
- Каждая строка: тип линзы · общая потребность · разбивка по филиалам.

**C. Drill-down по филиалу:**
- Линзы — SPH-диаграмма (есть в CRM, переиспользуем компонент).
- Оправы — кол-во по категориям.
- Расходники — пакеты/футляры/салфетки (из `pos_consumables`).

**Действие «Предложить закупку»** → bottom-sheet с автоматически собранным списком → создаёт запись в `manager_suggestions` (тип `procurement`) → пуш владельцу. Окончательное решение и фактический заказ делает владелец через CRM `/admin/lens-procurement` или `/admin/frame-procurement`.

### Экран 5. «Задачи» (Inbox)

URL: `/inbox`

Единая лента всего, что требует внимания. Сортировка: критичность ↓, время ↓.

**Типы задач:**

| Тип | Источник | Действия |
|---|---|---|
| 🔴 Service QA критика | `v_employee_discipline_status` + новые сигналы | ✅ Разобрал · 💬 Написать сотруднику · ⬆️ Эскалировать |
| 🟡 Жалоба клиента | `employee_feedback_responses` с rating ≤ 2 | ✅ Закрыто · 💬 Позвонить клиенту · ⬆️ Эскалировать |
| 📦 Заказ застрял | `orders` где `status_changed_at` > 10 дней | ✅ Решено · 📞 Связаться с филиалом |
| 💸 Предложение по зарплате | `manager_suggestions` со статусом `pending` (свои) | Только просмотр статуса (ждёт владельца) |
| 📦 Предложение по закупке | `manager_suggestions` тип `procurement` | Только просмотр статуса |
| 📅 Дедлайн в календаре | `franchise_calendar_events` audience=manager | ✅ Выполнено · ⏰ Перенести |
| 🚨 Дефицит критический | расчёт из `lens_purchase_batches` | 📦 Предложить закупку |
| 💬 Сообщение от франчайзи | `franchise_messages` (если оставите эту функцию) | 💬 Ответить · ⬆️ Эскалировать |

Каждая задача — карточка со свайп-действиями (вправо ✅, влево ⬆️).

## 5. Действия «Предложить владельцу»

Новая таблица `manager_suggestions`:

```sql
CREATE TABLE manager_suggestions (
  id            UUID PK,
  manager_id    UUID FK manager_users,
  type          TEXT,  -- 'payroll_adjustment' | 'procurement' | 'incident' | 'hiring'
  branch_id     UUID NULL,
  employee_id   UUID NULL,
  payload       JSONB, -- сумма, причина, список SKU и т.д.
  comment       TEXT,
  status        TEXT DEFAULT 'pending', -- 'pending' | 'approved' | 'rejected' | 'noted'
  owner_response TEXT NULL,
  created_at    TIMESTAMPTZ,
  resolved_at   TIMESTAMPTZ NULL
);
```

**Поток:**
1. Управляющий из любого экрана нажимает «Предложить ...».
2. Bottom-sheet с предзаполненными полями + поле «Комментарий владельцу».
3. Запись создаётся, пуш владельцу + строка в CRM (новый раздел `/admin/manager-suggestions`).
4. Владелец одобряет / отклоняет / откладывает.
5. Управляющая видит статус в задачах + получает уведомление о решении.

**В CRM нужно создать** новый раздел `/admin/manager-suggestions` для владельца — компактный inbox со swipe-actions.

## 6. Push-уведомления

### Каналы
- **Web push** через PWA (основной).
- **Telegram-бот** как дублирование для критических — на случай если PWA не доставил (iOS Safari капризный с push).
- **SMS как fallback** для самых критичных (опционально, через Zadarma).

### Какие события пушит

| Событие | Канал | Время |
|---|---|---|
| Продавец не открыл смену в 9:00 | Telegram + push | в 9:15 |
| Service QA: грубость / низкий скор < 60 | push | сразу после ингеста |
| Жалоба клиента (rating ≤ 2 в фидбэке) | push | сразу |
| Выручка филиала < 50% от плана к 18:00 | push | в 18:05 |
| Терминал не отвечает > 30 мин | push | через 30 мин после потери heartbeat |
| Дефицит линз < 5 дней по любому семейству | push | раз в день в 10:00 |
| Владелец одобрил/отклонил предложение | push | сразу |

### Настройки в портале
- Раздел `/settings/notifications` где управляющий может включать/отключать категории.
- «Тихие часы» (например, 22:00–8:00) — кроме самых критичных.

## 8. Что мы НЕ делаем (явно)

- Нет финансового дашборда P&L (это в CRM).
- Нет редактирования цен, тарифов, конфигурации системы.
- Нет прямого создания/удаления сотрудников (только предложение «нанять/уволить» с эскалацией).
- Нет создания закупок в БД — только формирование списка и эскалация.
- Нет редактирования заказов, возвратов, чеков — это POS/CRM.
- Нет франчайзи-функционала (`franchise_messages`, `franchise_documents`, `franchise_contracts` и т.д. — это `portal.refocus.asia`).
- Нет десктопной версии-полировки — портал спроектирован под телефон. На десктопе работает, но не оптимизирован.

## 9. Открытые вопросы для уточнения

1. **Чат сотрудник ↔ управляющая.** Делать ли отдельный чат внутри портала, или достаточно WhatsApp + пуш «Написать сотруднику»? Пока в плане — без чата, через WhatsApp deep-link.
2. **Доступ к мобильному приложению клиентов.** Должна ли видеть статистику мобильного приложения (DAU, новые скачивания)? Сейчас не включил.
3. **Кому из вас приходит уведомление о предложениях?** Только владельцу? Или дублировать франчайзи (если касается его филиала)?
4. **Telegram-бот для управляющей.** Делаем ли отдельный бот или пишем в существующий?
5. **Резервный логин.** Если управляющая забудет PIN — кто восстанавливает? Через owner-CRM или email-восстановление?
